# Full interactive terminal CLI

WinMon now has a read-only terminal frontend using Spectre.Console 0.54.0 and System.CommandLine 2.0.14 on .NET 10 Windows. It references the existing monitoring assemblies, never WPF. The original snapshot command remains a one-interval table/JSON report.

## Requirements and baseline

The full app goal covers Processes, Services, Usage and Connections, desktop query/measurement semantics, independent controls, selection/details, session pins, optional authenticated installed-service traffic, translations and verification. The atomic statuses and evidence live in [TERMINAL-CLI-CHECKLIST.md](TERMINAL-CLI-CHECKLIST.md). Baseline repository verification was green before this increment; prior uncommitted preview changes were preserved.

## Runtime and ownership

`MonitorSession` owns one-second native capture, baselines, delivery, history, usage totals and connection observations. Its post delegate sends drain callbacks to the terminal owner's queue. One synchronous input/render loop owns all delivered state and Spectre rendering; it never nests Spectre prompts. The command yields before entering that loop so the invoker registers cancellation. The loop processes keys every 50 ms and redraws on observations, keys, size or health changes.

The CLI retains up to 30 minutes within the existing process/connection entry budgets; service history keeps its existing two-minute window. Finite Process Top allows normal compaction while keeping pin/selection retention; All keeps full process observations subject to the same budget. Resource summaries represent the selected sample. Process/service CPU and I/O use the desktop's five-second window, GPU uses readable intervals and memory/counts remain point-in-time. Usage totals are cumulative and share the desktop busy-time denominator.

Pause keeps the selected full resource frame, its process averaging window, service/usage/connection observations and health states. Live capture continues. Resume selects the newest observations. Cell and detail text are deferred and cached for a stable row observation, with vertical scroll and horizontal panning for long paths/endpoints.

## Tabs and controls

| Tab | Queries and display |
| --- | --- |
| F1 Processes | Six metric sorts, executable grouping, text/PID/App only filters, Top/All, individual working set versus grouped private memory, metadata and full readings in details. Uses ProcessRanking, ProcessSearch, SampleList and ProcessPins. |
| F2 Services | CPU/private memory/I/O/name, all/running/stopped, Workers and search. Name requires All. Shared-host/service identity and individual host/worker observations are shown in details using ServiceRanking. |
| F3 Connections | Executable/lifetime grouping, endpoint/owner/PID/address search, App only, TCP/UDP, six traffic/count sorts, traffic periods and protocol/address/port/TCP-state details. ConnectionQuery and ConnectionTrafficTotals preserve availability, loss and incomplete coverage. |
| F4 Usage | CPU time, I/O, GPU time, lifetimes and last activity; search/App only, session start, Share and running/lifetime details. UsageQuery is shared with WPF UsageView.Visible. |

Each tab retains its filter, sort, Top, selection, view position and session pins. Keys 1–6 sort, slash edits the filter, Enter applies/opens details, Esc cancels/clears/returns, Up/Down/Page/Home/End select rows, and Left/Right reveal columns. T cycles 5/10/15/20/50/All, P pins, N filters to pins, G groups Processes, A filters Apps, S cycles Services status, W toggles workers and R cycles Connections periods (since start/60/300/1800 seconds). Question mark shows translated help, Space pauses, Q exits and Ctrl+C cancels.

Stable process keys include the lifetime domain, PID and creation token; grouped keys use executable identity. Pinned processes resolve through the shared pin model so an exited or inaccessible lifetime cannot borrow a reused PID's readings. Other missing pinned identities remain labeled unavailable and retain readable context. Pins are deliberately session-local and never modify desktop preferences.

## Layout and text

The minimum terminal size is 80×20. Text is literal, terminal control/format characters are removed, tabs in detail text become spaces, and Spectre's cell-width truncation keeps each table row on one line. The name column stays visible, the selected metric is revealed automatically, and other fields can be panned horizontally or inspected in details. Very small terminals show resize guidance while retaining quit/navigation input. Selection and pins have text markers, independent of color. Existing resource labels and new CLI help are translated across all ten UI languages.

At the 120x24 minimum for the wide layout, five CPU/Memory/Disk/Network/GPU panels occupy 119 cells. Titles match resource colors. CPU/memory/disk/GPU lead with percentages; Network leads with download speed on an automatic rate scale over the displayed minute. Secondary values below the bars mirror desktop: CPU GHz, used/total RAM GiB, disk MB/s, upload speed and GPU VRAM/3D. Resource histories cover 60 seconds and preserve gaps/source identity. The wide view ends at the panels and table paging reclaims the former disk/network detail rows. Compact/minimum layouts retain their height/details and use download units for network. Processes show numeric metrics without a History column or history footer. Pause freezes observations, histories and scales. Column panning, sampling and retention are unchanged.

## Optional traffic

`--network` connects to an already-installed local service through NetworkServiceClient's pipe protection and server identity checks. NetworkTrafficClient publishes immutable snapshots with one stable SessionId through reconnects. Calls are cancellation-bounded, unavailable snapshots become gaps, ordinary failures retry after five seconds, and protocol mismatch stops as UpdateRequired. Disposal cancels and awaits the active connection.

November 10 follow-up: traffic remains exclusively in Connections, with the same executable grouping as desktop. Explicit `network start` starts/checks the installed authorized service. Explicit `network install` installs/repairs and starts it through a linked compilation of the existing desktop NetworkSetupBroker and the same signed bundle assets, including UAC, authenticated setup and health-verified commit/rollback. Ordinary monitoring never installs anything. Missing signed assets and Store builds return guidance without launching setup. The command checks connectivity, preserves incomplete sample quality and does not enable a persistent desktop preference. Service removal remains outside this scope.

Without the flag, endpoint lists still work and traffic sorting falls back to TCP counts. With it, missing and incomplete rates/totals retain their quality markers. Native testing found the installed service genuinely reporting warming-up/incomplete/capacity-exceeded snapshots; the UI faithfully preserves those states rather than claiming working traffic rates. See the checklist for raw evidence.
