# Sensors settings and gauge readings

The hardware sensor controls live in Settings → Services alongside per-process network monitoring. See [Services settings](SERVICES-SETTINGS.md). The shared Celsius/Fahrenheit selector lives under Settings → Monitoring, beside the resource gauge options. The Store edition keeps the temperature unit and built-in sensor readings in the gauges and resource details.

The CPU, disk and GPU gauges use one subtitle. CPU pairs clock and temperature. Disk pairs throughput and drive temperature. GPU pairs temperature and the driver-reported power percentage. Missing sensors leave the remaining measurements visible. Fan speeds stay in the resource details, available on hover and keyboard focus. The CPU details group board channels labeled CPU separately from other named board fans.

The disk collector uses read-only Windows storage IOCTLs on a background task. It resolves the volume to one disk extent and reads the device temperature descriptor. Volumes that cannot be mapped unambiguously and devices that return no valid index-zero reading omit the temperature. The background cache has one outstanding query per configured volume, invalidates on a drive or sample reset, and expires values after 30 seconds. See [Windows volume extents](https://learn.microsoft.com/en-us/windows/win32/api/winioctl/ni-winioctl-ioctl_volume_get_volume_disk_extents) and [storage temperature data](https://learn.microsoft.com/en-us/windows/win32/api/winioctl/ns-winioctl-storage_temperature_info).

The signed optional sensor service reads supported board tachometers using [LibreHardwareMonitor 0.9.6](https://github.com/LibreHardwareMonitor/LibreHardwareMonitor/blob/v0.9.6/LibreHardwareMonitorLib/Hardware/Computer.cs). It sends up to 16 named channels as an optional field on the existing protocol. The client accepts only current, validated readings. CPU fan channels can show zero RPM. The System fans row shows running fans and collapses when all its channels report zero RPM. An older service continues to provide CPU temperature and needs a new signed package for fans.

[Temperature history and captures](TEMPERATURE-HISTORY.md) now persists CPU/GPU/disk temperatures, thermal zones and CPU limits, adds temperature charts and capture conditions, and retains minute temperature/limit peaks. Board fan readings remain session-only in restart history. Older recordings without temperature fields show unavailable readings. The Services page contains setup, status and maintenance controls.
