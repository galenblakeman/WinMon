# Hardware sensors in the desktop installer

Requested November 26, 2026. Add an unchecked hardware sensor task beside per-process network monitoring in the signed desktop installer, including silent installation of official PawnIO when it is missing.

The task explicitly names PawnIO and administrator approval. Each task is independent and is not selected again on upgrades. Packaging downloads the pinned official PawnIO 2.2.0 installer, checks SHA-256, and embeds the unmodified package only in the signed desktop installer. The pin and source URL live in `packaging/PawnIO.json`; the hash and silent switches are recorded in the [WinGet 2.2.0 manifest](https://github.com/microsoft/winget-pkgs/blob/master/manifests/n/namazso/PawnIO/2.2.0/namazso.PawnIO.installer.yaml). Unsigned installers omit the task and payload. No runtime download is needed.

After desktop files are installed, `InstallHardwareSensors` checks the 64-bit machine PawnIO uninstall registration. A registered package is preserved, including newer releases. Otherwise Setup extracts its temporary-only payload, verifies its hash again, and requests elevation for `PawnIO_setup.exe -install -silent`. Nonzero failures, declined elevation, hash errors or missing registration prevent sensor service installation. Exit 3010 requests a Windows restart; if registration is already present, sensor setup can proceed, with readings potentially unavailable until restart. Restart is handled through Inno Setup's normal `NeedRestart` behavior, including `/NORESTART` for unattended deployments.

The installer then invokes `WinMon.exe --install-sensor-service` as the original user. This entry point uses the existing sensor client and signed setup broker. The broker separately requests elevation, authenticates the requester, checks service health and retains transaction rollback. Successful setup persists `CpuTemperatureMonitoringEnabled` while preserving unrelated preferences. Update-in-progress and already-running-app guards return 1618 for both installer entry points. Failed sensor setup leaves desktop WinMon installed and tells users to retry in Settings → Services, after restart if requested. Silent installation logs failures without an extra dialog.

PawnIO is a shared system prerequisite and has its own installation lifecycle. Sensor setup failure does not roll it back, and WinMon removal does not uninstall it. The sensor helper itself still requires PawnIO; Settings enable/repair, background reconnect, portable startup and Store paths do not install the driver. The PawnIO installer is distributed unmodified; its own terms and registration remain intact.

Verification covers installer compilation with neither, either and both tasks; production Pascal orchestration with simulated OS boundaries; release hash rejection and unsigned omission; and preference persistence after successful, declined and failed sensor setup. The interactive tasks page is inspected before installation. Native clean-machine driver/service install, alternate administrator credentials, reboot and physical sensors require separate signed release acceptance and are not established by simulation.

Verification also exposed a stale restart-history test fixture: its reflection generator treated the live fan list and disk temperatures as persisted fields. The fixture now explicitly excludes those fields and asserts their omission on restore, matching the existing serializer. No production history format changed. All 28 restart-history tests pass after this correction.

What landed: the installer task, pinned offline prerequisite payload and app setup entry point. Departures: PawnIO and sensor service installation can each request administrator approval. PawnIO provisioning is confined to the installer; Settings retains its existing prerequisite behavior.

Validation on an isolated snapshot of `e611762` plus the installer change and fixture correction: desktop and Store solution/benchmark builds completed with zero warnings and errors; four installer configurations, 13 simulated orchestration scenarios and the release-signing/hash gates passed. All 1,399 MonCore tests passed. The full desktop run passed 11,427 tests and failed two UI diagnostics (`LanguageDiagnosticSavesEveryChoiceAndRestoresOriginalWindowState` and `MainDiagnosticAcceptsExactlyThreeSamplesButRejectsNonAdvancingRecordingAndRetainsTheSnapshot`); both passed when rerun individually in fresh test hosts. The Store unit-test run was stopped at the user's request before completion, and the planned Store installer/history integration run was not started. No tests were restarted after that request. Concurrent UI and temperature-history work was excluded from the verification snapshot. Native driver/service installation, reboot and physical sensor acceptance remain unverified.
