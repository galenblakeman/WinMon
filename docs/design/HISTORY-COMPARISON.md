## What landed

Validation: `tools/Verify.ps1 -Smoke capture` passed the app/benchmark builds with zero warnings/errors, all 2,011 executed desktop tests and 35 capture renders (`artifacts/verify/20261119-203613-197-desktop`). Both tabs were reviewed in light/dark at normal/minimum sizes. Expected explicit, elevation/package-dependent and Store-only checks were not executed by the desktop gate. The isolated analysis cost is recorded in `docs/PERFORMANCE-HISTORY.md`.

Implemented `IncidentTimeline.Compare`, the default Compare periods tab and Selected moment tab in `FlightRecorderWindow`, translations for all supported cultures, focused comparison tests and capture-smoke checks/renders for both tabs. The comparison runs only on navigation or refresh, outside the sampling path. No design departures; variable window lengths, time-weighted integration, per-process network joining and recording/export formats remain outside this feature.

Row-highlight follow-up: `FlightRecorderWindow.xaml` owns hover, selection and keyboard focus chrome for comparison, moment, event and crash rows. Raised theme surfaces retain normal text colors; an accent border marks selection even after focus leaves the list, and a text-colored outline marks keyboard focus. The crash row's accessibility style inherits the same chrome. Capture smoke renders selected rows in dark/light at both sizes, plus focused moment rows.

Follow-up validation: app/benchmark builds passed with no warnings and capture smoke passed with 57 renders (`artifacts/verify/20261125-191205-414-desktop`). Affected dark/light content renders were reviewed at normal/minimum sizes; Windows denied foreground activation, so native captions were not verified. The full unrestricted test run passed 11,185 tests with two search-diagnostic final-state failures; both affected methods passed all three cases when rerun alone (`artifacts/verify/history-highlight-search-recheck`). The full gate therefore recorded a failure despite the clean focused rerun.

Binding-error follow-up: navigation and snapshot replacement can detach rows from the window's implicit style, exposing a default alignment binding that cannot find an ancestor. `HistoryListView` now creates ordinary `ListViewItem` containers with local alignment values that survive detachment; it retains the existing highlight templates. The regression enables WPF binding tracing explicitly, reproduces the reported `HorizontalContentAlignment` error before the fix, and checks navigation, refresh, empty history and close afterward. This addresses container lifetime without changing the table layout or recording semantics.

Binding-fix validation: `tools/Verify.ps1 -TestFilter 'FullyQualifiedName~FlightRecorder'` passed app/benchmark builds with no warnings and all 22 selected History tests (`artifacts/verify/20261126-064457-832-desktop`). The regression filters alignment errors by `ListViewItem`, excluding deferred ComboBox diagnostics from other fixtures. Dark/light History content renders at normal/minimum sizes were reviewed. Both broader capture-smoke attempts completed History renders but timed out later in Settings (`20261126-064106-439-desktop` and `20261126-064312-767-desktop`), so the complete capture smoke did not pass and native captions remain unverified.
