# Tabbed Info

Selected design: progressive disclosure, with horizontal **Hardware | Guide | About** tabs in one resizable native WPF dialog. Keep theme colors and standard keyboard semantics. Use XAML for the window, tabs, help expanders and About; generate only hardware rows in code.

Hardware keeps every existing inventory section and selectable detail, with CPU initially expanded. Collapsed headers show the first nonempty line of their existing snapshot details on the right, trimmed visually with the complete summary in a tooltip and automation help text. Expanded headers hide that summary. Section labels explicitly use the theme Text brush rather than inheriting the toggle button foreground; regression tests cover light/dark text colors in both expansion states. This is a preview of the first item, not an aggregate or device count. Refresh replaces the snapshot. Copy includes every section and detail regardless of expansion. Collection remains off the UI thread and outside sampling, and closing the dialog ignores late results.

Guide provides five expandable task topics. The first opens by default. Its text was checked against `MainWindow.xaml.cs` (`SampleSelected`, `ReturnToLive`), `MainWindow.Snapshot.cs` (`OnSnapshotModeClick`, `CopySnapshot`), `MainWindow.Processes.cs`, `MainWindow.Export.cs`, `MainWindow.Captures.cs`, `MainWindow.Usage.cs`, `MainWindow.Services.cs` and the corresponding controls. Capture selects existing history while recording continues; it does not start a separate recording or open a per-resource detail window. Export distinguishes retained process observations from complete process recording. Usage aggregates by executable and Reset restarts its totals.

About reads assembly metadata through `AppInfo`. Its manual check calls `MainWindow.CheckForUpdatesAsync`, using the same client, cancellation and serialization gate as Settings and automatic checks. An open dialog follows check results, including automatic discovery and failures, through an owner-scoped notification. Busy checks/downloads disable duplicate actions. A retained offer survives a failed check; a withdrawn offer removes Update now. Closing the dialog unsubscribes the notification and ignores late results. Update now closes Info before invoking the existing main-window handler; signed verification, latest-offer recheck, cancellation, download, rollback and restart remain in that flow. Store builds expose only the Store-managed explanation.

All new text is in the English and nine translated resources. Existing Info button descriptions now include the guide and updates. Unit tests cover tab contents, busy/available/Store states, checking and failure, closing before handoff and late-result handling. Feature smoke captures hardware sections, all tabs in Dark/Light, and minimum-size scrolling; its update version is a fixture, not a published release.

## Landed and departures

Implemented in `HardwareInfoWindow.xaml` and its code-behind, with owner wiring in `MainWindow.xaml.cs` and status notifications in `MainWindow.Updates.cs`. The existing class name and Copy report format are preserved for callers. The mockup’s fabricated hardware summary and dates were omitted: the Hardware tab keeps the actual existing inventory, including motherboard and network adapters. The update progress/cancel controls remain in the main window after Info closes. Guide copy corrects the mockup’s invented per-resource history windows. Theme accent follows the selected WinMon palette rather than forcing cyan.
